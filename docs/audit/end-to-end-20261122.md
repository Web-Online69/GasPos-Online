# Audit GASPOS dari Hulu ke Hilir — 22 November 2026

## Ruang lingkup
Alur: Master Produk/Mitra → Pembelian Owner → Penerimaan Logistik → Stok → Surat Jalan → Pengiriman Sopir → Invoice Penjualan Owner → Pembayaran Keuangan → Laporan.

## Akar kesalahan penerimaan BEL 00005
Tabel `public.gas_logistics_requests` dahulu mempunyai constraint `UNIQUE(document_id)` yang membatasi penerimaan pada satu baris per dokumen. Satu dokumen pembelian bisa berisi banyak jenis produk atau diterima bertahap, sehingga terjadi `duplicate key value violates unique constraint gas_logistics_requests_document_id_key` untuk LPG 50 kg setelah LPG 12 kg lebih dahulu diterima.

Perbaikan telah diterapkan: constraint dokumen global dihapus dan diganti dengan unique index khusus `direction='OUT'` agar banyak penerimaan `IN` untuk satu pembelian diterima tanpa melemahkan keunikan dokumen pengiriman. File: `supabase/allow_multiple_purchase_receipts_per_document.sql`.

## Tindakan audit ini
1. **Regresi database di CI**: `scripts/audit/workflow-purchase-receipts.test.mjs` mensimulasikan penolakan penerimaan kedua pada aturan lama, penerimaan kedua yang berhasil setelah migrasi, dan duplikasi dokumen keluar yang tetap ditolak. Ada pula cek aturan stok/harga pembelian tabung kosong.
2. **Perketat hak akses**: `supabase/audit_restrict_receipt_finance_read.sql` mencabut akses anonim terhadap ringkasan keuangan, progres penerimaan, dan RPC penerimaan tabung kosong mandiri. Progres pembelian pada view dibatasi ke Owner dan Logistik, tanpa mengubah data transaksi.
3. **Audit integritas siap diulang**: `scripts/audit/live-integrity.sql` bersifat read-only, memeriksa 9 kondisi lintas alur dan mengembalikan kolom `status` PASS/REVIEW.

## Belum dapat dinyatakan lulus secara menyeluruh
- Pengujian klik dan simpan transaksi nyata di perangkat HP menggunakan seluruh akun kerja belum dilakukan. Jangan memakai transaksi produksi sebagai fixture uji.
- Jaringan browser/seluler dapat gagal di luar kendali aplikasi. Pengiriman ulang dengan ID permintaan melindungi pembelian dari duplikasi, tetapi tidak menjamin internet stabil.
- Audit keamanan Supabase masih memperingatkan beberapa `SECURITY DEFINER` view/function. Izin anonim pada tiga jalur penting sudah ditutup; review implementasi security-invoker dan RLS seluruh objek lain memerlukan validasi hak akses setiap peran sebelum diubah.
- Simulasi UI Owner sebagai administrator menjalankan fungsi pekerjaan Sopir/Logistik melalui RPC server masih memerlukan verifikasi dengan akun asli. Menu yang terlihat tidak otomatis membuktikan otorisasi RPC.
- Uji regresi yang ditambahkan menutup penyebab constraint BEL 00005, tetapi pengujian baseline lainnya belum sepenuhnya memuat semua migrasi database produksi terbaru.

## Prosedur pengendalian setelah perubahan
Jalankan `npm run test:audit`, `npm run test:members`, `npm run test:flow`, `npm run test:workflow-ui`, dan `npm run build` sebelum deploy. Jalankan `scripts/audit/live-integrity.sql` terhadap database secara read-only setelah perubahan skema transaksi penting. Jika ada `REVIEW`, teliti data dan transaksi terkait **tanpa mengubah stok secara manual**.
